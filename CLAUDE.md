# Token-saving working agreement

Follow these to minimize token use. Quality first; trim waste, not substance.

## Responses
- Be concise. No preamble, no recap of what you just did, no filler.
- Answer the question asked; don't volunteer tangents.
- Explain only when asked, or when a choice is non-obvious. Keep it short.
- Don't restate file contents back to the user after editing.

## Files & search
- Don't re-read a file already read this session.
- Read only the needed part (use offset/limit), not whole large files.
- Prefer targeted Grep/Glob over broad scans. Stop once you have the answer.

## Tools
- Batch independent tool calls in one turn (run in parallel).
- Don't verify an edit by re-reading; the edit tool already confirms it.
- Avoid speculative exploration. If unsure of intent, ask one short question.

## Output
- Don't dump large command output; summarize unless asked for the raw text.
- Use small, focused diffs.
